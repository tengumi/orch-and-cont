# Лабораторная работа 1. Dockerfile

Для лабораторной мы использовали API заметок на FastAPI. Приложение
позволяет добавлять заметки и получать их список. Данные сохраняются
в файле notes.jsonl. Для хранения подключён volume notes-data к /app/data.

## Плохой и хороший Dockerfile

| Плохая практика | Почему плохо | Как исправлено |
| --- | --- | --- |
| Базовый образ python:latest | Версия Python может измениться при следующей сборке | Указан python:3.12.7-slim-bookworm |
| Запуск приложения от root | Процесс получает лишние права внутри контейнера | Создан пользователь appuser с UID 10001 |
| COPY всего проекта перед установкой зависимостей | Изменение кода сбрасывает кеш слоя установки зависимостей | Сначала копируется requirements.txt, затем устанавливаются зависимости и копируется app.py |
| Сохранение кеша pip | Кеш занимает лишнее место в образе | Добавлен параметр --no-cache-dir |
| CMD в shell-форме | Промежуточная оболочка может не передавать сигнал остановки серверу | Использована exec-форма CMD |

В хорошем варианте также использован уменьшенный образ slim.
Файл .dockerignore исключает из контекста сборки локальные данные,
окружение Python, кеш и служебные файлы.

## Плохие практики использования контейнера

1. Хранить важные данные только внутри контейнера без volume.
   При удалении контейнера эти данные будут потеряны.
2. Запускать приложение с --privileged без необходимости.
   Это даёт контейнеру избыточные права и доступ к устройствам хоста.

## Когда не стоит использовать контейнеры

1. Когда приложению необходимо другое ядро ОС. Например,
   Windows-приложение нельзя запустить в обычном Linux-контейнере.
   В таком случае нужна подходящая ОС или виртуальная машина.
2. Для разового локального скрипта без сложных зависимостей,
   если подготовка и поддержка контейнера не дают практической пользы.
